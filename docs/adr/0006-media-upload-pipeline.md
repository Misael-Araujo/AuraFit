# ADR 0006: Media upload pipeline and moderation gate

- **Status:** Accepted
- **Decision:** Accept multipart image uploads through the API, validate and normalize them server-side, check moderation before they are considered usable, and store them in a private S3-compatible bucket under `users/{userId}/...` with presigned GET URLs for read access. Client-side direct uploads are not used yet because the API must enforce consent, validation, and moderation before a file becomes part of a user profile or avatar workflow.
- **Context:** Face photos and derived assets are sensitive biometric data. The platform requires robust validation, retention controls, and a consistent moderation decision before a media asset can be consumed by later avatar or AI-processing workflows. Direct presigned PUT uploads are convenient but would bypass server-side validation and allow untrusted or unsafe files into the object store before policy checks run.
- **Consequences:** The API remains the single point of trust for file acceptance, reduces attack surface, and gives us a clear place to enforce type checks, pixel limits, and moderation decisions. The trade-off is an extra hop through the application server, which is acceptable for the MVP because image processing, security gates, and auditability are more important than raw upload throughput.
- **Alternatives:** Presigned client uploads to MinIO/S3 immediately (rejected because they bypass moderation and validation) and raw server-buffered uploads without normalization (rejected because metadata stripping and decompression-bomb guards would be inconsistent and difficult to audit).
